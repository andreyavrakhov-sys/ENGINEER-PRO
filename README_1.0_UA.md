# ENGINEER PRO 1.0 — налаштування

## Стан реалізації
- Windows 0.9.0: початкові JS-модулі й функції збережені; додано окреме вікно ручної синхронізації.
- Android: окремий початковий мобільний клієнт для нотаток/завдань, **не повний функціональний аналог Windows**.
- Синхронізація: ручне вивантаження/завантаження **всього JSON стану**, без злиття конфліктів. Останнє завантаження перезаписує хмарний стан. Файли документів та секретні API-ключі не синхронізуються.
- EXE/APK не перевірені фактичним збиранням у цьому середовищі. GitHub Actions налаштовані для перевірки у CI.

## Supabase
1. Створіть проєкт Supabase.
2. В SQL Editor виконайте `supabase/schema.sql` (одноразово).
3. В Authentication увімкніть Email/Password і створіть власного користувача (або зареєструйте через панель).
4. Скопіюйте Project URL та **publishable/anon key** із налаштувань API. Ніколи не використовуйте `service_role`/secret key у клієнті.
5. У Windows натисніть «☁ Синхронізація», введіть URL, ключ, email, пароль; натисніть вивантаження.
6. У Android введіть ті самі дані та натисніть «Отримати дані з хмари».
7. Зміни Android збережіть у хмару, потім на Windows натисніть завантаження і перезапустіть програму.

## GitHub
Розпакуйте ZIP у репозиторій GitHub (зберігайте структуру). У Actions запустіть `ENGINEER PRO 1.0 builds` → Run workflow. У разі успішного збирання EXE і debug APK з'являться в Artifacts. Для Play Store потрібні окремі підписування та release-процедура.

## Локальні команди
Windows: `npm install`, `npm run check`, `npm start`, `npm run dist`.
Android: `cd android`, `npm install`, `npx cap add android`, `npx cap sync android`, `cd android`, `./gradlew assembleDebug` (потрібні JDK 17 та Android SDK).

## Обмеження
Немає автоматичної фонової синхронізації, синхронізації файлів, офлайн-черги чи вирішення конфліктів. Не використовуйте одночасне редагування на двох пристроях без послідовного обміну. Android-клієнт — MVP. Для промислового використання потрібні інтеграційні тести та резервне копіювання Supabase.
